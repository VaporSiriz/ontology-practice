# 03. 비슷한 개념과의 차이

온톨로지라는 말은 여러 기술과 겹친다. 이 회차는 자주 혼동되는 개념을 정리한다.

## 한눈에 비교

| 개념 | 주로 담는 것 | 관계 종류 | 기계가 추론하는가 | 대표 예 |
|---|---|---|---|---|
| 용어집 (glossary) | 용어와 뜻풀이 | 거의 없음 | 아니오 | 사내 용어 사전 |
| 택소노미 (taxonomy) | 계층 분류 | 상하위(is-a) | 제한적 | 생물 분류, 상품 카테고리 |
| 시소러스 (thesaurus) | 용어와 동의어·상하위·연관어 | 동의어, 상하위, 연관 | 제한적 | 도서관 주제명표목, SKOS 기반 어휘 |
| 온톨로지 (ontology) | 클래스, 관계, 속성, 공리 | 임의의 관계 + 공리 | 예 | OWL로 쓴 도메인 모델 |
| 지식 그래프 (knowledge graph) | 실제 개체와 사실 (데이터) | 임의의 관계 | 종종 | 검색 엔진의 개체 패널 |
| 데이터베이스 스키마 | 테이블, 컬럼, 제약 | 외래키 | 아니오 (제약 검사만) | RDB 테이블 정의 |

## 1. 택소노미 vs 온톨로지

택소노미는 **하나의 관계(상하위)만** 쓴다. 온톨로지는 여러 종류의 관계와 공리를 쓴다.

```
택소노미:                  온톨로지:
Book                      Book ──writtenBy──► Author
 └─ Novel                  Book ──publishedBy──► Publisher
                           Novel ⊑ Book    (is-a)
                           Loan ──forBook──► Book
```

택소노미는 "무엇의 한 종류인가"만 말한다. 온톨로지는 "무엇과 어떻게 연결되는가"까지 말한다.

## 2. 지식 그래프 vs 온톨로지

이 둘은 자주 같이 언급되고 실제로 겹친다.

- **온톨로지**는 **스키마**다. "책은 저자가 있다"는 규칙을 적는다.
- **지식 그래프**는 **데이터**다. "book_1984는 writtenBy george_orwell이다"라는 사실을 담는다.

온톨로지 없이 지식 그래프만 있으면, 노드와 엣지의 의미가 시스템마다 달라진다. 온톨로지는 그 의미를 고정한다.

반대로 온톨로지만 있고 개체가 없으면 쓸모가 제한적이다. 두 가지를 같이 만들어야 한다.

## 3. 온톨로지 vs 데이터베이스 스키마

이 차이는 실무에서 가장 중요하다.

| 항목 | 데이터베이스 스키마 | 온톨로지 |
|---|---|---|
| 세계 가정 | 닫힌 세계 (Closed World): 기록되지 않은 것은 거짓 | 열린 세계 (Open World): 기록되지 않은 것은 모른다 |
| 제약의 역할 | 위반 데이터를 **거부**한다 | 위반을 **검사**하고, 명시되지 않은 사실을 **추론**한다 |
| 이름의 의미 | 테이블과 컬럼 이름은 그 DB 안에서만 뜻이 있다 | IRI로 식별되어 외부에서도 같은 뜻이다 |
| 상속 | 보통 없음 (있어도 제한적) | 클래스 상속과 관계 추론이 기본 |

### 열린 세계 vs 닫힌 세계

예를 들어 DB에 `Loan(id=7, member=kim)`만 있다고 하자. 

- **닫힌 세계**: "7번 대출에는 책이 없다"고 본다. `book` 칸이 비어 있으므로 책이 없는 것이다.
- **열린 세계**: "7번 대출에 책이 있는지 아직 모른다"고 본다. 정보가 없다는 것이 없다는 뜻은 아니다.

온톨로지가 열린 세계를 쓰는 이유는 여러 출처의 데이터를 합칠 때 생긴다. 한 시스템에 정보가 없다고 해서 세상에 없는 것은 아니기 때문이다.

## 4. 시소러스 vs 온톨로지

시소러스는 **단어**를 중심으로 한다. 같은 뜻의 단어(동의어)와 가까운 단어(연관어)를 묶는다. 온톨로지는 **개념**을 중심으로 하고, 개념 사이의 의미 있는 관계와 제약을 적는다.

- 시소러스: "회원"의 동의어는 "이용자", "patron"이다.
- 온톨로지: `Member`는 `Person`의 하위 클래스이고, `Loan`은 `Member`를 가진다.

SKOS는 시소러스 구조를 RDF로 표현하는 표준이다. SKOS 자체는 온톨로지보다 가벼운 모델이고, 대부분의 공리를 담지 않는다. 그래서 SKOS는 "어휘 체계"이고 OWL은 "온톨로지 언어"라고 구분하는 것이 일반적이다.

## 5. 용어 정리 체크리스트

새로운 용어를 만났을 때 다음 질문으로 분류해 본다.

1. 뜻풀이만 있는가? → 용어집
2. 상하위 계층만 있는가? → 택소노미
3. 동의어와 연관어가 있는가? → 시소러스
4. 여러 관계와 공리가 있고 추론이 목적인가? → 온톨로지
5. 실제 개체와 사실이 쌓여 있는가? → 지식 그래프 (데이터 쪽)
6. 테이블, 컬럼, 제약만 있는가? → DB 스키마

## 실습 질문

1. 도서관의 "주제명표목"(예: "소설-한국")은 시소러스인가 온톨로지인가? 이유는?
2. DB에 `Member.email`이 `NOT NULL`로 되어 있다. 온톨로지에서 같은 내용을 적으면 어떻게 달라지는가?
3. 두 도서관 DB를 합칠 때, 한쪽이 "대출 중 여부"를 기록하지 않는다면 닫힌 세계와 열린 세계 중 무엇을 가정해야 하는가?

## 요약

- 택소노미는 계층, 시소러스는 어휘, 온톨로지는 **관계와 공리를 가진 개념 모델**이다.
- 지식 그래프는 **데이터**이고, 온톨로지는 그 데이터의 **의미를 정하는 스키마**다.
- DB 스키마는 닫힌 세계에서 **제약을 검사**하고, 온톨로지는 열린 세계에서 **추론**한다.
