# 02. 핵심 구성 요소

온톨로지를 이루는 재료는 대체로 다섯 가지다. 이 회차는 각각을 도서관 예시로 확인한다.

## 1. 클래스 (Class)

**개념의 집합**이다. 공통된 성질을 가진 개체들을 묶는다.

```
Book      : 책
Author    : 저자
Member    : 회원
Loan      : 대출
```

클래스는 "무엇이 있는가"를 나타낸다. 클래스 사이에는 **상하위 관계(subclass)**를 둘 수 있다.

```
Book
 ├─ Novel        (소설)
 └─ Poetry       (시집)
```

"Novel은 Book의 하위 클래스다"라는 말은 "모든 소설은 책이다"라는 뜻이다. 이 관계를 **is-a 관계**라고 부른다.

## 2. 개체 (Individual, Instance)

**클래스에 속한 구체적인 대상**이다.

```
book_1984      : Book      (소설 『1984』의 이 한 권)
author_orwell  : Author    (조지 오웰)
```

클래스와 개체를 구분하는 것이 중요하다.

- 클래스 `Book`은 "책이라는 개념"이다.
- 개체 `book_1984`는 "그 개념에 속하는 특정한 책"이다.

## 3. 관계 (Object Property)

**두 개체 사이의 연결**이다. 관계는 "누가 누구와 어떤 관계인가"를 나타낸다.

```
writtenBy   : Book  → Author      (책은 저자에 의해 쓰였다)
borrowedBy  : Loan  → Member      (대출은 회원에 의해 이뤄졌다)
forBook     : Loan  → Book        (대출은 책에 대한 것이다)
```

관계에는 보통 **정의역(domain)**과 **치역(range)**을 적는다. `writtenBy`의 정의역은 `Book`, 치역은 `Author`다. 정의역과 치역은 "이 관계는 어떤 종류의 개체 사이에서만 성립하는가"를 제한한다.

관계에는 성질도 붙일 수 있다.

- **대칭**: `isSameEditionAs(A, B)`이면 `isSameEditionAs(B, A)`
- **추이**: `isPartOf`에서 A ⊂ B, B ⊂ C이면 A ⊂ C
- **역관계**: `wrote`의 역은 `writtenBy`

## 4. 속성 (Data Property)

**개체가 가진 값**이다. 관계가 개체와 개체를 잇는다면, 속성은 개체와 리터럴 값(문자열, 숫자, 날짜 등)을 잇는다.

```
title        : Book → string        ("1984")
publishedYear: Book → integer       (1949)
loanDays     : Loan → integer       (14)
dueDate      : Loan → date          (2026-11-24)
```

관계와 속성의 구분은 실무에서 헷갈리기 쉽다. 판단 기준은 **끝이 개체인가, 값인가**다.

## 5. 공리와 제약 (Axioms, Constraints)

**명시적으로 적어 둔 참인 규칙**이다. 여기서부터 추론이 시작된다.

| 종류 | 예 | 뜻 |
|---|---|---|
| 카디널리티 | 모든 `Loan`은 정확히 하나의 `Book`을 가진다 | 대출 한 건은 한 권에 대한 것이다 |
| 값 제약 | `loanDays`는 양의 정수다 | 0일이나 음수 대출은 없다 |
| 존재 제약 | 모든 `Book`은 최소 한 명의 `Author`를 가진다 | 저자 없는 책은 없다 |
| 분리 | `Novel`과 `Poetry`는 공통 개체가 없다 | 한 책이 소설이면서 시집일 수 없다 |
| 등가 | `Patron`과 `Member`는 같은 클래스다 | 두 이름이 같은 개념이다 |

공리는 **데이터를 막기 위한 장치**가 아니다. 어떤 것이 **참이라고 선언하는 것**이다. 이 점이 데이터베이스 제약과 다르다. 자세한 차이는 03회차에서 다룬다.

## 6. 이 다섯 가지의 관계

```
          ┌────── 클래스 (Book, Member, Loan)
          │          ▲ 개체가 속함
          │          │
 온톨로지 ─┼────── 개체 (book_1984, member_kim)
          │          │
          ├────── 관계 (borrowedBy: Loan → Member)
          │
          ├────── 속성 (loanDays: Loan → 14)
          │
          └────── 공리 (모든 Loan은 정확히 하나의 Book을 가진다)
```

## 7. 용어 정리

- **TBox** (terminological box): 클래스, 관계, 속성, 공리. 개념의 구조 자체다.
- **ABox** (assertional box): 개체와 그 사실. "book_1984는 Book이고 writtenBy george_orwell이다."

TBox는 스키마에 가깝고, ABox는 데이터에 가깝다. 둘을 합쳐야 추론이 일어난다.

## 실습 질문

1. `Loan`이 `Member`를 관계로 가리키는 것과, `Member`의 이름을 속성으로 가지는 것은 무엇이 다른가?
2. "책은 반드시 제목을 가진다"는 공리인가, 속성의 값 제약인가? 이유는?
3. `Novel`이 `Book`의 하위 클래스이고, `book_1984`가 `Novel`이라는 사실을 알면 무엇을 추론할 수 있는가?

## 요약

- **클래스**: 개념의 집합. **개체**: 그 개념의 구체적 대상.
- **관계**: 개체와 개체의 연결. **속성**: 개체와 값의 연결.
- **공리**: 참이라고 선언한 규칙. 추론의 출발점.
